# Helmsman × Ember longitudinal campaign — internal assessment

## Verdict

**Corpus grade: D — failed longitudinal campaign.**

The product was often a strong live thinking partner: it landed the No.8
instance walk, 90-day cash calendar, Q4 decomposition, community-number cleanup,
reversible pricing test, and several owner/date gates. But the campaign's core
longitudinal promise did not hold. Wrong-company research contaminated the
profile; corrections did not fully displace stale state; structured memory was
unavailable across all six Compass surfaces after Run C; Decision Log retained
only one earlier entry; and chat repeatedly used persistence verbs before writes
were verified.

This was a cumulative exploratory campaign because no reset was exposed. The
platform build/version was unavailable, so the three runs are not controlled
longitudinal comparisons across a known build. Founder runs were clean tasks.
Across the campaign there were **44 substantive founder turns and 40 visible
founder/Helm exchanges**: Run A **14/13**, Run B **15/14**, and Run C **15/13**
(Run C's 13 includes the closing acknowledgement and its **three substantive
misses**). ## Recommended follow-ups

1. Make write semantics transactional: `pending` → server-confirmed `saved` →
   read-after-write verified. Ban “recorded/captured/ready” before the final state.
   Reproduce against the [Run C persistence sequence](artifacts/2026-08-13-helmsman-ember-longitudinal/run-c/raw-run.md#persistence-and-propagation-evidence).
2. Add entity-resolution quarantine before research reaches Company Profile;
   correction must delete/supersede every stale field atomically and retain an
   audit trail. Use the [Run B wrong-company case](artifacts/2026-08-13-helmsman-ember-longitudinal/run-b/raw-run.md#profile--memory-state) as the regression fixture.
3. Establish one authoritative decision object shared by chat, Commitments,
   Focus, Goals, and Decision Log, including status/reversal/supersession links.
   Regression target: [single-entry Decision Log](artifacts/2026-08-13-helmsman-ember-longitudinal/run-c/06-decision-log-single-prior-entry.png).
4. Replace empty outage fallbacks with last-known-good read-only state plus
   freshness and availability timestamps. Do not render empty as if it were
   current. Regression target: [post-sweep Commitments](artifacts/2026-08-13-helmsman-ember-longitudinal/post-sweep/commitments.png).
5. Add retrieval provenance to every recalled fact: source conversation/card,
   captured-at time, confidence, and superseded-by. Retest the exact [Run C
